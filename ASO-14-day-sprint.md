# ContactIn WordPress.org 14-Day Ranking Sprint

Purpose: improve legitimate visibility for high-relevance searches by strengthening relevance, trust, and conversion signals.

## Success Criteria (Day 14)

- Plugin page shows current release metadata (v1.1.4 and updated readme snippet).
- Ranking improvement on at least 5 mid-tail queries.
- Support first-response median under 24 hours.
- Support resolved ratio at or above 90% for sprint period.
- At least 1 new user review from genuine support/help interaction.

## Daily Cadence (14 Days)

### Day 1
- Confirm WordPress.org reflects latest SVN commit metadata.
- Record baseline rankings for all tracked queries.
- Save screenshots of each query result page where ContactIn appears.

### Day 2
- Review support forum and respond to all open threads.
- Mark resolved items accurately after confirmation.
- Capture support metrics: first response time, resolved ratio.

### Day 3
- Tighten plugin screenshots captions on readme for intent clarity:
  - contact form database
  - lead capture workflow
  - anti-spam and reliability
- Keep claims specific and provable.

### Day 4
- Publish one short tutorial on site/blog:
  - "How to save contact form submissions in WordPress database"
- Link naturally from plugin page support replies when relevant.

### Day 5
- Re-check ranking movement for primary queries.
- Identify top 3 underperforming terms by worst position.
- Note which intent phrases are missing from visible snippet.

### Day 6
- Support sweep: reply/resolve quickly.
- Ask satisfied users for honest review only after issue resolution.

### Day 7
- Ship one meaningful small improvement (bugfix or UX gain).
- Update changelog with user-facing value, not vague wording.

### Day 8
- Re-test all queries.
- Compare week-over-week delta vs Day 1 baseline.
- Tag queries as Improved / Flat / Down.

### Day 9
- Publish second intent article:
  - "Anti-spam contact form setup with reCAPTCHA and honeypot"
- Add clear setup steps and troubleshooting section.

### Day 10
- Update FAQ emphasis based on real support questions.
- Keep FAQ headings in natural user language.

### Day 11
- Support and review follow-up sweep.
- Ensure unresolved threads are actively progressing.

### Day 12
- Re-run ranking checks.
- Focus on secondary terms now that primary terms stabilize.

### Day 13
- Prepare sprint summary:
  - query deltas
  - support metrics
  - installs trend
  - review changes

### Day 14
- Final measurement run.
- Decide next 30-day strategy by query cluster performance.

## Decision Rules (What To Change Next)

- If brand query rank is not #1:
  - verify slug visibility, metadata sync, and plugin title consistency.
- If primary queries are flat for 7+ days:
  - improve screenshot captions and first 2 description paragraphs around those intents.
- If impressions rise but positions do not:
  - strengthen relevance language in FAQ and top description (no stuffing).
- If positions rise but installs do not:
  - improve snippet clarity, screenshots #1/#2, and first-value bullets.
- If support resolved ratio drops under 90%:
  - prioritize support SLA before new optimization edits.

## Guardrails (Stay Compliant)

- No misleading tags or unsupported claims.
- No fake reviews or incentivized manipulative behavior.
- No keyword stuffing.
- Every update must include real user-facing value.
- Keep release cadence meaningful (target every 45-90 days).

## Weekly KPI Dashboard

Track weekly:
- Avg rank (primary queries)
- Avg rank (secondary queries)
- Brand rank
- Search snippet match rate
- Support first response median
- Support resolved ratio
- New reviews count
- Active installs trend

## Expected Outcome Window

- Metadata/index refresh: typically hours to a couple days.
- Mid-tail rank movement: usually 1 to 4 weeks.
- Broad head-term movement ("contact form"): often requires longer trust/usage accumulation.
